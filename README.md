# RefCheck: 논문 검토 도우미 (MVP)

## 쓰는 법

1. `RefCheck.html`을 **Chrome 또는 Edge**에서 엽니다 (더블클릭). 설치할 것은 없고, 학술 API를 부르기 때문에 인터넷 연결은 필요합니다.
2. 첫 화면의 상자를 누르거나 PDF를 창에 끌어다 놓습니다. 오른쪽 위 **업로드 아이콘**으로도 열 수 있습니다.
3. 10~30초 뒤 한 화면에 세 영역이 나란히 나옵니다: **I. 중복성 검토 · II. 참고문헌 검증 · III. 유사 주제 연구**. 내용이 길면 영역마다 안에서 스크롤됩니다. (창 너비가 1100px보다 좁으면 위아래로 쌓입니다.)
4. 결과는 브라우저에 자동 저장됩니다. 왼쪽 위 **검토 이력**에서 다시 열 수 있습니다.

오른쪽 위 아이콘 버튼 (마우스를 올리면 이름이 나옵니다):

| 아이콘 | 기능 |
|---|---|
| 문서 | 원고 PDF 업로드 |
| 줄 그은 문서 | **요약 보고서**: 종합 판단과 자동 생성 의견을 담은 A4 보고서를 새 탭으로 엽니다. 인쇄·PDF 저장, Markdown 저장, 종합 의견 복사 |
| 표 | Excel 내보내기 (시트 4개: 요약 · 중복성 · Reference · 유사연구) |
| 아래 화살표 | 이력 백업 (JSON 파일로 저장) |
| 되돌리기 화살표 | 백업에서 복원 |
| 슬라이더 | 설정: 중복성 "주의" 기준값(기본 40%), 유사 논문 수(기본 20), API 연락용 이메일(선택) |

- **초록 · 추출 정보 · 메모:** 원고 제목 오른쪽의 세 버튼입니다. 추출 정보에서는 뽑아낸 키워드와 참고문헌 원문 블록을 볼 수 있어서, 참고문헌 개수가 맞는지 확인할 수 있습니다. 메모는 입력하는 대로 저장됩니다.
- **이력 백업:** 검토 이력은 브라우저 안에 저장됩니다. 브라우저의 "인터넷 사용 기록 삭제"에서 사이트 데이터까지 지우면 이력도 함께 지워집니다. 가끔 백업해 두세요.

## Supabase 저장 (선택)

설정하지 않으면 검토 이력은 이 브라우저(IndexedDB)에만 저장됩니다. Supabase에 연결하면 로그인한 계정으로 저장되어 다른 PC나 브라우저에서도 볼 수 있습니다.

1. **테이블 만들기:** Supabase 대시보드 → SQL Editor에서 [`supabase/schema.sql`](supabase/schema.sql)을 실행합니다. 테이블 3개(`reviews`, `review_references`, `user_settings`)가 생기고, 로그인한 본인 행만 다룰 수 있도록 RLS가 켜집니다. 로그인하지 않은 요청(anon)에는 권한이 없습니다.
2. **계정 만들기:** Authentication → Users → **Add user**에서 이메일과 비밀번호로 계정을 만듭니다("Auto Confirm User" 체크). 혼자 쓴다면 Authentication → Sign In / Providers에서 **Allow new users to sign up**을 꺼 두세요.
3. **주소·키 넣기:** 프로젝트 폴더의 `.env.local`에 아래 두 줄을 넣고, 설정 파일을 만듭니다.
   ```
   SUPABASE_URL=https://<프로젝트>.supabase.co
   SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
   ```
   ```bash
   powershell -ExecutionPolicy Bypass -File tools\make-config.ps1
   ```
   브라우저에서 바로 여는 앱은 `.env.local`을 읽을 수 없어서, 이 스크립트가 값을 `js/config.local.js`로 옮겨 줍니다. 두 파일 모두 `.gitignore`에 있어 저장소에 올라가지 않습니다.
4. **로그인:** `RefCheck.html`을 열면 오른쪽 위에 **로그인** 버튼이 생깁니다. 로그인하면 버튼이 초록색으로 바뀌고 이메일이 표시됩니다. 이때부터 새 검토, 메모, 설정이 Supabase에 저장됩니다.
5. **기존 이력 옮기기:** 로그인한 뒤 계정 버튼을 누르면, 이 브라우저에만 있던 검토를 **Supabase로 옮기기**로 올릴 수 있습니다. 이미 올린 검토는 건너뛰고, 브라우저에 있던 원본은 그대로 남습니다.

API 응답 캐시(CrossRef·OpenAlex)는 공개 데이터라 로그인 여부와 관계없이 브라우저에만 저장합니다.

## Vercel 배포

저장소를 Vercel에 가져오면(Import) [`vercel.json`](vercel.json) 설정대로 빌드됩니다. 빌드 스크립트 [`tools/vercel-build.sh`](tools/vercel-build.sh)가 앱 파일을 `dist/`로 복사하고, `RefCheck.html`을 첫 화면(`index.html`)으로 둡니다.

- Vercel 프로젝트 → Settings → **Environment Variables**에 `SUPABASE_URL`과 `SUPABASE_PUBLISHABLE_KEY`를 넣으면, 빌드할 때 `js/config.local.js`를 만들어 Supabase 로그인을 켭니다. 값을 넣거나 바꾼 뒤에는 다시 배포(Redeploy)해야 반영됩니다.
- 두 값이 없으면 Supabase 없이 브라우저 저장만으로 동작합니다.
- 검토 이력(브라우저 저장)은 사이트 주소마다 따로 생깁니다. 파일로 열 때의 이력은 Vercel 주소에서 보이지 않으니, 로그인 후 "Supabase로 옮기기"나 백업·복원으로 옮기세요.

## 요약 보고서

결과를 연 상태에서 툴바의 **요약 보고서** 버튼을 누르면 자동으로 만들어집니다.

- **종합 판단:** 중복성이 기준 이상이거나 X·확인 못 함 참고문헌이 있으면 "확인 필요 — …", 없으면 "특이사항 없음"
- **핵심 수치:** 중복성 %, 참고문헌 O/X, 유사 연구 편수(최근 3년)
- **종합 의견 3문장:** 결과 수치로 자동 작성 (AI가 아니라 규칙 기반이라 결과가 항상 같습니다)
- **표:** 유사도 상위 대상, 확인이 필요한 참고문헌(사유 포함), 유사 주제 연구 상위 5편, 검토자 메모
- **내보내기:** 인쇄 / PDF로 저장(A4), Markdown 저장, 종합 의견만 복사. Excel 내보내기의 첫 시트 "요약"에도 같은 내용이 들어갑니다

팝업이 막힌 환경에서는 보고서가 HTML 파일로 내려받아집니다.

## 판정 기준

| 화면 | 기준 |
|---|---|
| Reference **O** | CrossRef 또는 OpenAlex에서 찾았고, 제목 유사도 85 이상, 제1저자·연도 일치 |
| Reference **X** | 못 찾음 / 제목만 비슷함 / 연도 불일치 / 제1저자 불일치 / DOI 오류. 이유는 사유 칸에 적힘 |
| "(경미)" | 연도가 1년 차이이고 프리프린트(arXiv 등)가 끼어 있는 경우. X로 두지만 대개 문제없음 |
| "(참고)" | 저널·학회명 표기가 DB와 다름. 약어 차이가 흔해서 O/X에는 반영하지 않음 |
| **–** (확인 못 함) | 네트워크 오류, 또는 한글 문헌이라 국내 DB(KCI)가 필요한 경우 |
| 중복성 | TF-IDF 코사인 유사도. 전체 점수 = 가장 비슷한 1편의 점수. 외부 논문은 초록 단위, 이전 투고분은 본문 앞부분까지 비교 |

- 「학습 가능한…」 6번: 제1저자를 "H. Zang"으로 적었으나 실제는 **Heng Zhang** → 실제 오기

- 「시그멘테이션…」 1번은 PDF가 영어 단어를 줄 끝에서 하이픈 없이 잘라 놓아("usi / ng") 처음에 제목 불일치로 나왔습니다. 잘린 단어도 맞춰 보도록 고친 뒤 O로 나옵니다

**중복성에서 발견한 것:** 「실내 저조도…」 PDF는 OpenAlex에 이미 출판된 같은 논문(대한공간정보학회지 2024, 국문 초록)과 **82%** 로 "주의"가 떴습니다. 국문 요약까지 비교하기 때문에 잡힌 결과입니다.

## 알려진 한계

- **영어 논문 우선.** 영문 초록이 있는 국내 논문은 읽을 수 있게 했습니다("요약/要旨", "참고문헌", "핵심용어" 등 인식). 다만 한글로 쓴 참고문헌은 KCI 연동(v2) 전까지 "확인 못 함"으로 나옵니다.
- **Semantic Scholar 미사용.** API 키 없이 요청하면 첫 요청부터 한도 초과(429)로 거절되어 뺐습니다. 조회 순서는 CrossRef → OpenAlex입니다.
- **CrossRef 속도.** 이메일 없이 쓰면 동시 요청이 1개로 제한되어 참고문헌 1건에 약 1초 걸립니다. 설정에 이메일을 넣으면 3개까지 늘어납니다.
- **이전 투고분끼리의 유사도.** 같은 분야(영상 강화)의 한글 논문끼리는 공통 단어 때문에 20% 안팎이 나옵니다. 기준값 40%보다 낮아 "주의"는 뜨지 않습니다.
